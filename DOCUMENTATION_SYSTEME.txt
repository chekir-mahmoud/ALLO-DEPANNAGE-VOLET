2. BASE DE DONNEES (SUPABASE)
================================================================================

TABLE: annonces
---------------
- id (UUID)                 --> Identifiant unique
- reference (VARCHAR)       --> Reference auto-generee (YYMMDD-XXX)
- titre (VARCHAR)           --> Titre de l'annonce
- message (TEXT)            --> Description detaillee
- departement (VARCHAR)     --> Code departement (ex: "gironde")
- ville (VARCHAR)           --> Ville
- service (VARCHAR)         --> Type de service (ex: "debarras-maison")
- type_client (VARCHAR)     --> "particulier" ou "professionnel"
- budget (VARCHAR)          --> Budget estime
- urgence (BOOLEAN)         --> Demande urgente
- statut (VARCHAR)          --> "disponible", "en_cours", "termine"
- mise_en_avant (BOOLEAN)   --> Annonce mise en avant
- contact_nom (VARCHAR)     --> Nom du contact
- contact_telephone (VARCHAR) --> Telephone
- contact_email (VARCHAR)   --> Email (optionnel)
- contact_ville (VARCHAR)   --> Ville du contact
- created_at (TIMESTAMP)    --> Date de creation
- updated_at (TIMESTAMP)    --> Date de mise a jour

TABLE: professionals
--------------------
- id (UUID)                 --> Identifiant unique
- user_id (UUID)            --> Reference vers auth.users
- nom (VARCHAR)             --> Nom du professionnel
- email (VARCHAR)           --> Email (unique)
- telephone (VARCHAR)       --> Telephone
- siret (VARCHAR)           --> Numero SIRET (optionnel)
- nom_entreprise (VARCHAR)  --> Nom de l'entreprise (optionnel)
- ville (VARCHAR)           --> Ville
- statut (VARCHAR)          --> "en_attente", "valide", "refuse", "suspendu"
- created_at (TIMESTAMP)    --> Date d'inscription
- updated_at (TIMESTAMP)    --> Date de mise a jour
- validated_at (TIMESTAMP)  --> Date de validation par admin
- validated_by (UUID)       --> Admin qui a valide

TABLE: access_requests
----------------------
- id (UUID)                 --> Identifiant unique
- professional_id (UUID)    --> Reference vers professionals
- annonce_id (UUID)         --> Reference vers annonces
- statut (VARCHAR)          --> "en_attente", "accorde", "refuse"
- created_at (TIMESTAMP)    --> Date de la demande
- updated_at (TIMESTAMP)    --> Date de mise a jour
- processed_at (TIMESTAMP)  --> Date de traitement par admin
- processed_by (UUID)       --> Admin qui a traite
- UNIQUE(professional_id, annonce_id) --> Une seule demande par pro par annonce

TABLE: admin_notifications
--------------------------
- id (UUID)                 --> Identifiant unique
- type (VARCHAR)            --> "new_professional", "access_request", "new_annonce"
- reference_id (UUID)       --> ID de l'element concerne
- is_read (BOOLEAN)         --> Notification lue ou non
- created_at (TIMESTAMP)    --> Date de creation

FONCTIONS SQL:
--------------
- generate_reference()      --> Genere la reference auto (YYMMDD-XXX)
- update_updated_at_column() --> Met a jour updated_at automatiquement
- notify_new_professional() --> Cree notification admin pour nouveau pro
- notify_access_request()   --> Cree notification admin pour demande d'acces
- register_professional()   --> Inscrit un pro (SECURITY DEFINER, bypass RLS)

3. AUTHENTIFICATION
================================================================================

ADMIN:
------
- Connexion via /auth/login
- Utilise Supabase Auth
- Metadata: raw_user_meta_data.is_admin = true
- Acces a /admin/annonces (page unifiee avec onglets)

PROFESSIONNELS:
---------------
- Inscription via /pro/inscription
  - Champs: nom, email, mot de passe, telephone, SIRET, entreprise, ville
  - Cree un compte Supabase Auth + profil dans table professionals
  - Statut initial: "en_attente"
  - Notification admin automatique

- Connexion via /pro/connexion
  - Verifie que le compte est valide (statut = "valide")
  - Si en_attente: message d'attente de validation
  - Si refuse/suspendu: acces refuse

- Acces aux annonces: /annonces
  - Requiert un compte pro valide
  - Peut voir toutes les annonces
  - Peut demander acces aux coordonnees

4. FLUX UTILISATEUR
================================================================================

A. INSCRIPTION PRO:
-------------------
1. Pro remplit formulaire /pro/inscription
2. Compte Supabase Auth cree
3. Profil insere dans professionals (via RPC register_professional)
4. Notification admin creee automatiquement (trigger)
5. Email envoye a l'admin (notification)
6. Pro voit message "en attente de validation"

B. VALIDATION PRO (ADMIN):
--------------------------
1. Admin voit badge notification dans onglet "Professionnels"
2. Admin clique "Valider" ou "Refuser"
3. Statut mis a jour dans professionals
4. Notification marquee comme lue
5. Email envoye au pro (si valide)

C. CONSULTATION ANNONCES (PRO VALIDE):
--------------------------------------
1. Pro se connecte via /pro/connexion
2. Redirection vers /annonces
3. Pro voit toutes les annonces sans coordonnees
4. Pro peut filtrer par departement, service, statut

D. DEMANDE D'ACCES COORDONNEES:
-------------------------------
1. Pro clique "Demander acces" sur une annonce
2. Demande inseree dans access_requests (statut: en_attente)
3. Notification admin creee automatiquement (trigger)
4. Email envoye a l'admin + au client (si email fourni)
5. Pro voit "Demande envoyee"

E. TRAITEMENT DEMANDE (ADMIN):
------------------------------
1. Admin voit badge notification dans onglet "Demandes d'acces"
2. Admin clique "Accorder" ou "Refuser"
3. Statut mis a jour dans access_requests
4. Notification marquee comme lue
5. Email envoye au pro avec coordonnees (si accorde)
6. Pro peut maintenant voir les coordonnees sur l'annonce

5. EMAILS (RESEND)
================================================================================

Configuration requise:
- Variable d'environnement: RESEND_API_KEY
- Expediteur: noreply@debarreo.fr

Types d'emails:
---------------
1. new_professional     --> Admin notifie d'une nouvelle inscription pro
2. pro_validated        --> Pro notifie que son compte est valide
3. access_request       --> Admin + Client notifies d'une demande d'acces
4. access_granted       --> Pro recoit les coordonnees du client

Gestion des erreurs:
- Les erreurs d'email ne bloquent pas les operations
- Rate limit gere gracieusement (log warning, continue)


================================================================================
6. SECURITE (RLS - Row Level Security)
================================================================================

TABLE annonces:
- SELECT: public (tout le monde peut lire)
- INSERT/UPDATE/DELETE: admin uniquement

TABLE professionals:
- SELECT own: pro peut voir son propre profil
- SELECT all: admin peut voir tous les profils
- INSERT: utilisateur authentifie (via RPC pour bypass)
- UPDATE own: pro peut modifier son profil
- UPDATE all: admin peut modifier tous les profils

TABLE access_requests:
- SELECT own: pro peut voir ses propres demandes
- SELECT all: admin peut voir toutes les demandes
- INSERT: pro valide uniquement
- UPDATE: admin uniquement

TABLE admin_notifications:
- ALL: admin uniquement
